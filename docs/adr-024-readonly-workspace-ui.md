# ADR-024 — Disposable Workspace UI and nonced editor styling

14 September 2026. Phase 5 adds Files/Git/Changes views with the same read-only behaviours in a desktop pane and full-screen mobile dialog. The view uses the local cookie-scoped API from ADR-022 and confined Git reader from ADR-023. It never changes Hermes chat state, sends project files to the agent, or persists previews/diffs.

Workspace and CodeMirror are lazy chunks; language packages load on demand for JavaScript/TypeScript, JSON, Python and YAML. Unknown formats and Git patches remain inert text. Both CodeMirror readOnly and editable=false are set; there are no save/upload/stage/commit actions. Binary/oversized/blocked paths have explicit states. Copy and attachment download require deliberate user actions. A per-view epoch and abort controller discard late reads across file/root/session/profile/account changes. Closing, backgrounding, going offline or verifying access clears the private view; returning re-reads through the same native admission boundary.

CodeMirror generates trusted editor styles. HTML gets a random 18-byte per-response style nonce and matching CSP style-src allowance, passed through EditorView.cspNonce. Script policy remains self-only, without unsafe-inline or unsafe-eval. No project HTML/SVG is injected. A cached public shell retains its matching header/nonce; this is not user/session data. Old public shells without a nonce use plain-text preview. Missing editor chunks likewise degrade to inert text.

The mobile view has safe-area/VisualViewport sizing, 44px controls, visible Back to chat and native dialog focus/Escape behaviour. Tabs implement arrows/Home/End. Preview Back restores the originating control synchronously during layout, avoiding delayed focus stealing. Browser back/history routing is not repurposed to store workspace content or paths. Project folder filtering applies to the current bounded directory page, not a recursive search engine.

Local verification: production build/typecheck/lint, six isolated Chromium component cases (1440/430/320 widths, dark/light, keyboard, diff, binary, reduced height, 44px targets and axe), and API/store wire tests. Component tests use in-memory API responses; they are not browser-network, native-Hermes, Docker or physical-device acceptance. Complete application E2E/HTTPS/container acceptance is required before Phase 5 sign-off. The original physical-phone Phase 4 gate remains independently open.
